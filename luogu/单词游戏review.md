```cpp
#include <iostream> 
#include <vector> 
#include <cstring> 
#include <algorithm> 
using namespace std; 
const int N = 20; 

// dp[mask][i]: 
// mask 表示当前哪些单词已经被使用了 (第 j 位为 1 表示第 j 个单词已用) 
// i 表示接下来要拼接的单词必须要以元音 i 结尾 (0:A, 1:E, 2:I, 3:O, 4:U) 
int dp[1 << N][5]; 

int n; 
string words[N]; // 直接用数组存单词，利用下标 0~n-1 来区分，解决重复单词的问题 

int CharToInt(char c){ 
	if(c == 'A') return 0; 
	if(c == 'E') return 1; 
	if(c == 'I') return 2; 
	if(c == 'O') return 3; 
	if(c == 'U') return 4; 
	return -1; 
} 
int dfs(int i, int mask){ 
	// 如果这个状态之前计算过，直接返回 
	if(dp[mask][i] != -1) return dp[mask][i]; 
	
	int res = 0; 
	// 遍历所有单词 
	for(int j = 0; j < n; j++){ 
		// 条件 1：该单词还没有被使用过 (!(mask & (1 << j))) 
		// 条件 2：该单词的结尾字母恰好是我们需要的字母 i 
		if(!(mask & (1 << j)) && CharToInt(words[j].back()) == i){ 
		
			// 下一个拼接的单词的结尾，必须是当前单词的开头 
			int next_i = CharToInt(words[j][0]); 
			
			// 标记当前单词已使用 (mask | (1 << j))，并向下递归 
			int t = dfs(next_i, mask | (1 << j));
			
			res = max(res, t + (int)words[j].length()); 
		} 
	 }
	 
	 // 记忆化并返回 
	 return dp[mask][i] = res; 
} 
	int main(){ 
	ios::sync_with_stdio(false); 
	cin.tie(nullptr); 
	if (!(cin >> n)) return 0; 
	for(int i = 0; i < n; i++){ cin >> words[i]; } 
	 
	// 初始化 dp 数组为 -1 
	memset(dp, -1, sizeof dp); 
	
	int ans = 0; 
	// 尝试以任意元音作为整条链的最末尾的字母 
	for(int i = 0; i < 5; i++){ 
		ans = max(ans, dfs(i, 0)); // 初始时 mask = 0 (所有单词都没用过) 
	} 
	
	cout << ans << "\n"; 
	return 0; 
}
```
### 第一步：认清本质与“无后效性”原则

这道题的本质是：给定 $N$ 个单词，找出一条路径（单词链），使得相邻两个单词的“首尾字母”匹配，并且路径上单词的总长度最大，每个单词最多用一次。

**1. 为什么你的第一次尝试失败了？**
动态规划（记忆化搜索）有一个极其重要的铁律——**无后效性**。
意思是说：**当我们记录下某个状态的答案后，这个答案必须是绝对客观的，不能受到“你是通过什么路径来到这个状态”的影响。**

在你的初版代码中，状态是 `dp[step][i]`（剩下 step 个单词，需要找以 i 结尾的单词）：
* 假设 **路线 A** 走了 3 步到达 `(step=5, i='E')`，此时用掉了单词 `["APPLE", "EAGLE", "ELEPHANT"]`。
* 假设 **路线 B** 也走了 3 步到达 `(step=5, i='E')`，但用掉的是 `["ORANGE", "EAGLE", "EAT"]`。
* 显然，路线 A 和路线 B 接下来可以使用的剩余单词是**完全不同**的。
* 如果你用全局变量 `mp`（map）来记录单词使用情况，当路线 B 访问 `dp[5]['E']` 时，它会直接读取路线 A 存入的答案。但路线 A 的答案是基于路线 A 的剩余单词算出来的，对路线 B 来说根本不适用！这就叫**状态定义不完整，产生了后效性**。

**结论**：要让记忆化生效，**“当前还剩哪些单词可用”必须成为 DP 状态的一部分**。

---

### 第二步：引入“状态压缩”（Bitmask）

既然我们需要把“单词的使用情况”存进 DP 状态里，而 $N \le 20$，这就到了**状态压缩（状压 DP）**出场的时候了。

我们可以用一个整数的**二进制表示**来记录这 $N$ 个单词到底谁用了、谁没用。
* 假设有 5 个单词，编号 0 到 4。
* 整数 `mask = 9`，它的二进制是 `01001`。
* 从右往左看，第 0 位是 1，第 3 位是 1，说明**第 0 个和第 3 个单词已经被使用了**，其余没被使用。

**位运算的常用操作：**
1. **检查第 $j$ 个单词是否被使用过**：`(mask & (1 << j))`。如果结果非 0，说明已使用；如果为 0，说明未使用。
2. **把第 $j$ 个单词标记为已使用**：`mask | (1 << j)`。

### 第三步：重新设计记忆化搜索 (DFS + Memoization)

现在我们有了完美的状态表示方法，重新定义 DFS。

#### 1. 状态定义
`dp[mask][i]` 表示：
* **当前单词的使用状态**为 `mask`（二进制位中 1 表示已用，0 表示未用）。
* **当前我们需要寻找一个以字母 `i` 结尾的单词**（0表示A，1表示E，2表示I，3表示O，4表示U）。
* **存放的值**：在上述条件下，继续往下拼接单词，所能获得的最大长度。

#### 2. 状态转移（递归逻辑）
为了和你的初版代码逻辑保持一致，我们采用**“从后往前倒推”**的接龙方式。
假设我们现在的要求是：**找一个以字母 `i` 结尾的单词**。

遍历所有 $N$ 个单词（设当前遍历到第 $j$ 个单词）：
1. **可用性检查**：它必须还没被用过 `!(mask & (1 << j))`。
2. **尾字母检查**：它的尾字母必须恰好是 `i`。
3. **递归推导**：如果选中了这个单词 $j$，那么接龙规则要求：**下一个我们要找的单词的尾字母，必须是当前单词 $j$ 的首字母！**
   * *举例：我们要找以 `E` 结尾的单词，我们挑中了 `APPLE` (A开头，E结尾)。那么在 `APPLE` 的前面，必须接一个以 `A` 结尾的单词。*
4. **状态更新**：选中单词 $j$ 后，新的状态变成 `mask | (1 << j)`（标记已使用），要求寻找的新字母变成 `CharToInt(words[j][0])`。
5. **计算最大值**：当前的最大长度 = 单词 $j$ 的长度 + 继续递归得到的结果。

#### 3. 递归的终止条件
* 不需要显式的终止条件。当所有未使用的单词都无法匹配当前的尾字母 `i` 时，`for` 循环结束，直接返回初始值 `0`，表示后续无法再接龙了。

### 第四步：完整逻辑图解分析

假设输入 3 个单词：
0: `A--E` (长4)
1: `E--O` (长5)
2: `I--A` (长6)

1. **起点**：我们在 `main` 函数里枚举整条接龙的**最终尾字母**。假设我们从 `O` 开始（即 `i=3`，`mask=000`）。调用 `dfs(3, 0)`。
2. **寻找尾部为 O 的单词**：
   * 找到单词 1 `E--O`。未使用，且尾部是 `O`。
   * 下一步我们需要找尾部是 `E` 的单词。状态变为 `mask=010` (十进制2)，调用 `dfs(1, 2)`。
3. **寻找尾部为 E 的单词**：
   * 此时 `mask=010`。
   * 找到单词 0 `A--E`。未使用，尾部是 `E`。
   * 下一步我们需要找尾部是 `A` 的单词。状态变为 `mask=011` (十进制3)，调用 `dfs(0, 3)`。
4. **寻找尾部为 A 的单词**：
   * 此时 `mask=011`。
   * 找到单词 2 `I--A`。未使用，尾部是 `A`。
   * 下一步需要找尾部是 `I` 的单词。状态变为 `mask=111` (十进制7)，调用 `dfs(2, 7)`。
5. **寻找尾部为 I 的单词**：
   * 此时 `mask=111`（所有单词都用光了）。
   * 没有单词符合条件。返回 0。
6. **回归计算长度**：
   * 单词 2 `I--A` 的结果 = 0 + 6 = 6，存入 `dp[3][0]`。
   * 单词 0 `A--E` 的结果 = 6 + 4 = 10，存入 `dp[2][1]`。
   * 单词 1 `E--O` 的结果 = 10 + 5 = 15，存入 `dp[0][3]`。
   * 最大长度就是 15。

如果中间有其他的搜索路径再次抵达了 `dp[2][1]`（也就是使用了单词 1，且需要找结尾为 E 的单词），程序就会直接 `return 10`，避免重复计算，这就实现了完美的**记忆化**。

### 第五步：复杂度为什么能 AC？

* **状态数量 (空间复杂度)**：`mask` 的取值范围是 $0 \sim 2^{20}-1$（大约 $10^6$），`i` 的取值是 $0 \sim 4$。所以 `dp` 数组的大小是 $10^6 \times 5 \times 4$ 字节 $\approx 20 \text{ MB}$。这在普通算法题（通常给 128MB 或 256MB）中完全合法。
* **转移时间 (时间复杂度)**：对于每个状态，我们最多遍历 $N$ 个单词（$N=20$）。总计算次数大约是 $10^6 \times 5 \times 20 \approx 10^8$ 次。配合记忆化的剪枝（很多状态实际上是达不到的），实际运行时间远小于 1 秒，能够轻松 AC（Accepted）。

### 总结
1. **遇到 N 比较小 ($N \le 20$)，且每个元素“选或不选”、“用或不用”的问题，第一时间想到状态压缩（位运算）。**
2. **记忆化搜索的 `dp` 数组必须包含所有能影响未来决策的变量。如果存在“使用过的元素不能再用”的规则，那么“哪些元素被用过了”就必须塞进 DP 的状态里。**
