


这道题的 DFS（记忆化搜索）部分是整个解法的灵魂。为了让你彻底掌握，我们抛开代码，从**“为什么要这么设计”**到**“具体是怎么一步步执行的”**，把这个 DFS 的思路掰开揉碎了详细讲一遍。

---

### 核心思想：记录“多走的冤枉路”

题目要求找出长度不超过 `最短路 + K` 的路径。由于 $K$ 非常小（$K \le 50$），我们不要去记录“当前走过的总长度”，而是去记录**“相比最短路，我们多走了多少距离”**（你可以理解为**“偏差值”**或**“冤枉路”**）。

### 1. 状态定义：`dp[u][j]`
在 DFS 中，我们定义 `dp[u][j]` 表示：
**从起点 `1` 走到节点 `u`，且当前走的路径长度比 `1` 到 `u` 的最短路恰好长了 `j` 的合法路径总数。**
* 举个例子：如果 `1` 到 `u` 最短路是 10，那么 `dp[u][2]` 就表示从起点到 `u`，路径总长度恰好为 $10 + 2 = 12$ 的路径条数。

我们最终要求的答案，就是走到终点 $N$，且多走的距离 $j$ 在 $0 \sim K$ 之间的路径总和：
$\sum_{j=0}^{K} dp[N][j]$。

---

### 2. 状态转移：为什么建反图？如何倒推？

我们从终点 $N$ 开始**倒着往前搜**。
假设我们现在处于节点 $u$，并且允许比最短路多走 $j$ 的距离。我们想知道有哪些路能走到当前状态。

在原图中，有一条边是从 $v$ 指向 $u$（即 $v \xrightarrow{w} u$），边权为 $w$。
在我们的**反图**（`rg`）中，我们正站在 $u$，顺着反向边找到了前驱节点 $v$。

**关键推导：状态 $j$ 是怎么变化的？**
1. 此时，从起点走到 $u$ 的实际路径长度是：`dis[u] + j`。
2. 因为最后一步是从 $v$ 走过长度为 $w$ 的边来到 $u$ 的，所以**从起点走到 $v$ 的实际路径长度**必须是：`(dis[u] + j) - w`。
3. 那么，走到 $v$ 时，相比于 $v$ 的最短路，**多走了多少距离呢？** 我们设它为 `j_prev`。
   `j_prev = 走到 v 的实际长度 - v 的最短路`
   **`j_prev = (dis[u] + j - w) - dis[v]`**

**结论：** 
如果我们要计算 `dp[u][j]`，只需要把所有指向 $u$ 的前驱节点 $v$ 找出来，计算出它们对应的 `j_prev`。只要这个 `j_prev` 在合法范围（$0 \le j\_prev \le K$）内，就把 `dp[v][j_prev]` 累加过来。

---

### 3. 判 0 环：怎么发现无数条路径？

题目里有一个大坑：**权值为 0 的边**。
如果图里存在一个由 0 边组成的环，而这个环恰好在某条合法路径上，那么策策就可以在这个环里绕无数圈，导致合法路线有无穷多条（输出 `-1`）。

**DFS 怎么抓 0 环？**
利用“递归调用栈”。
我们在搜索时，维护一个布尔数组 `ins[u][j]`，表示状态 `(u, j)` 是否**正在当前的递归链条中**。
* 当我们进入 `dfs(u, j)` 时，标记 `ins[u][j] = true`。
* 当我们准备退出 `dfs(u, j)` 时，撤销标记 `ins[u][j] = false`。

**为什么这样能抓到 0 环？**
你想，如果我们在 $u$ 点绕了一个权值为 0 的环，绕完一圈回到 $u$ 时，因为边权都是 0，多走的距离 $j$ **完全没有增加**（$j\_prev$ 算出来还是 $j$）。
所以，我们会再次试图调用 `dfs(u, j)`。
此时我们一查 `ins[u][j]`，发现它竟然已经是 `true` 了！这就意味着我们**在同一个状态里死循环了**，立刻判定存在 0 环，返回 `-1`。

（注：如果绕的是正权值的环，$j$ 必然会变大，调用的是 `dfs(u, j')`，$j \neq j'$，就不会触发 `ins[u][j] == true` 的报警，且当 $j' > K$ 时自然会停止递归，不会死循环。）

---

### 4. 完整的 DFS 逻辑梳理

我们把上面的思想串联起来，DFS 的执行步骤如下：

**起点调用：** 外部通过 `for (j = 0 -> K)` 依次调用 `dfs(N, j)`。

**进入 `dfs(u, j)`：**
1. **查岗 1（判环）**：检查 `ins[u][j]` 是否为 `true`。如果是，抓到 0 环，直接返回 `-1` 向上报警。
2. **查岗 2（记忆化）**：检查 `dp[u][j]` 是否算过了（不等于 `-1`）。如果算过了，直接返回答案，避免重复计算（不加这一步会超时）。
3. **入栈打卡**：标记 `ins[u][j] = true`。
4. **初始化答案**：令 `res = 0`。
   * **特殊的边界情况**：如果当前走到了起点 `u == 1`，并且多走的距离恰好 `j == 0`，说明这本身就是一条合法的最短路，让 `res = 1`。（注意：这里不能直接 `return 1`，因为起点也可能被 0 环包含，还需要继续搜其他边）。
5. **遍历反向边**：对于所有指向 $u$ 的节点 $v$（边权为 $w$）：
   * 计算前驱状态：`j_prev = dis[u] + j - w - dis[v]`。
   * 判断合法性：如果 $0 \le j\_prev \le K$。
   * 递归调用：`val = dfs(v, j_prev)`。
   * 如果 `val` 是 `-1`（下面发现了 0 环），当前层也立刻向上返回 `-1`。
   * 否则，把 `val` 加到 `res` 里（记得取模 $P$）。
6. **退栈销假**：标记 `ins[u][j] = false`。
7. **保存并返回**：把算出的 `res` 存入 `dp[u][j]`，并返回 `res`。

### 总结

这个 DFS 的精妙之处在于：
1. **反向搜索**：从终点找起点，只会遍历到那些**“真正能通向终点”**的状态，剪去了大量无效的死胡同。
2. **偏差值作状态**：抛弃了庞大的“总距离”，巧妙利用 $K \le 50$ 的特性，把状态压缩到极限（`N * 50`）。
3. **0环检测机制**：利用 0 环“只绕路、不增加偏差值”的本质，通过简单的 `ins` 数组栈标记，完美破解了判环难题。
